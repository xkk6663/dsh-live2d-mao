# 7.6 横条通道契约 · `window.__mioPetStrip`

> 出稿：pet-plugin-dev（task-4）｜契约归属：**插件侧**（本文件为唯一权威）
> 主体侧实现：Lead（`澪Agent应用/dist/live2d-pet/`）｜排障人：下一位接手者
> 关联：`docs/项目接管执行方案.md` §18（需求登记）、技术方案 §3.5（插件不得改核心 DOM）

---

## 0. 为什么需要这条通道

§18 登记的需求：把桌宠侧「可拖动 + 可关闭横条」复用为 **DSH 流式提示的专用窗位**，
与说话气泡（`#speech-bubble`）**互斥占用** —— 流式走横条、说话走气泡，不再打架。

**现状**：桌宠主窗口的插件通道**只有气泡**（`live2d-pet.js:3605` 的
`window.__mioPetBubble = { show, hide, isVisible, setEnabled }`），**没有横条 API**。
而被复用的横条实物在**另一个窗口**（`dist/live2d-pet/xiaozhi/xiaozhi-chat.html`）。

**做法**（文档 §18 原文即如此预设）：
> "横条组件**若需主体暴露，走 `window.__mioPet*` 通道**，与 `__mioPetBubble` 同一模式。"

⇒ 主体**新增**一条 `window.__mioPetStrip` 通道；插件只经它访问，**不碰任何 DOM/CSS**。
§3.5 禁的是"插件直接改核心 DOM"（曾导致"停用插件后气泡整个消失"），不是"新增通道"。

## 1. 职责分界（**关键**，别搞反）

| 归属 | 内容 | 持久性 |
|---|---|---|
| **主体** | 横条 DOM、**拖动位置**、**关闭态**、主题类应用 | **跨会话持久**（重启后位置/皮肤还在） |
| **插件** | 何时推内容、何时抑制、与气泡的互斥编排 | **会话内**（热重载即重置） |

> ⚠ **拖动位置与关闭态必须放主体**。若放插件，插件热重载/重装就会丢掉用户拖好的位置
> 与"我已关掉"的状态 —— 那正是 DSH 插件最常见的状态丢失事故。

## 2. 接口

```ts
window.__mioPetStrip = {
  // 显示/更新横条内容。幂等：同文本重复调用不产生额外动效。
  show(text: string, opts?: {
    sessionId?: string      // 主体侧据此区分来源（可选）
    sticky?: boolean        // true = 不清除自动隐藏计时（流式持续追加时用）
    durationMs?: number     // 0/缺省 = 由主体决定默认时长
  }): boolean               // false = 主体拒绝（例如用户已 ✕ 关闭）

  // 追加一个 token（流式打字机）。与 show 共用同一缓冲区。
  append(token: string, opts?: { sessionId?: string }): boolean

  // 隐藏横条**内容**（不改变"用户已关闭"状态）。
  hide(): void

  isVisible(): boolean
  isDismissed(): boolean               // 用户是否已在本会话/本机 ✕ 关闭（主体持久化）
  setEnabled(on: boolean): void        // 全局开关；false 后 show/append 一律返回 false
  applyStyle(styleId: string): string  // 返回实际生效的 styleId
  info(): { visible: boolean, dismissed: boolean, enabled: boolean, styleId: string }
}
```

### 铁律（三条，缺一不可）

1. **任何方法都不得抛异常**。主体实现必须内部兜底并返回安全值
   （`show`/`append` 返回 `false`，其余返回空值）。
   *理由*：插件在事件回调里调用它，抛出会污染 DSH 的事件流。
2. `show`/`append` 在**「已被 ✕ 关闭」「被 setEnabled(false) 禁用」「横条未挂载」**
   三种情况下都返回 `false`，插件据此**静默降级**，不得重试风暴。
3. `hide()` **只隐藏内容**，**不得**把 `isDismissed()` 置真 ——
   否则"插件切走内容"会被误当成"用户关闭了横条"。

### 主题

- 键：**`live2d_strip_style`（主键，推荐）**，`pet_strip_style`（**别名，同样认**）
  - 主键与 `live2d_bubble_style` **同族**，设置页「泡泡」扩展「横条」目标时最一致；
  - **两端都认这两个键**，避免"插件叫一套、主体叫一套"的键名漂移
    （主体侧见 `澪Agent应用/dist/live2d-pet/live2d-pet.js` 的 `__mioPetStrip` 实现）。
  - 插件侧常量 `STRIP_STYLE_KEY = 'pet_strip_style'` 仅用于**诊断/文档**展示；
    实际换肤一律经 `applyStyle(styleId)` **委托主体**，插件不自己读写 settings。
- 存储：**服务端 settings**（不是插件自存）
- 热应用：**`settings_changed`** 事件 → 主体重新 `applyStyle`。
  与 `live2d-pet.js` 里 `bs.setStyle(...)` / `__mioPetBubbleStyles` 那条既有通路完全一致。
- **泡泡界面**扩展一个「横条」目标即可复用整条链路。
- 插件**只调 `applyStyle` 请求**，自己不落类、不写 localStorage。

## 3. 四条验收与归属

| # | 验收 | 归属 | 插件侧落点 |
|---|---|---|---|
| ① | 流式提示显示在横条内、**可拖动**、**✕ 可关** | 显示=插件；拖动/✕=**主体** | `strip.pushStream(text, {append})` |
| ② | 气泡与横条**不同时弹同一内容** | **插件**（互斥状态机） | `pushBubble` 检测 `mode===STRIP && 同 key` → 拒绝 |
| ③ | 横条主题/颜色可在「泡泡」界面自定义 | 配置页=主体；请求=插件 | `strip.applyStyle(id)` |
| ④ | **关闭后本次会话不再自动弹**（下次流式再弹） | **插件**（会话级抑制） | `strip.markDismissed(sessionId)` |

④ 的语义边界（易混）：
- 主体 `isDismissed()`：**跨会话持久**的界面关闭态；
- 插件 `suppressedSessions`：**本会话**内"关过就不再自动弹"，会话结束即清。
  两者都要有，语义不同，**不要互相替代**。

## 4. 优雅降级

`window.__mioPetStrip` 不存在时（主体尚未实现 / 旧版桌宠），
插件 `lib/strip.js` 自动回落到 `window.__mioPetBubble`：

- 功能**不丢**（流式内容仍会显示）；
- 验收 ① 的"在横条内/可拖动"**不成立**（这是降级，不是缺陷）；
- **只告警一次**，不报错、不刷屏。

⇒ **主体侧未上线之前，插件全部测试仍是绿的**。

## 4.5 运行前置（**真机联调前必读**）

### ⚠ 8000 端口那个后端是**旧进程**，没有 ingest 路由

- `POST /api/plugin/dsh/ingest` 在**新代码里已实现**，但**当前正在跑的 8000 进程是旧进程**，
  打它会得到 **404**。
- ⇒ **真机联调前需由用户重启后端**。
  桌宠由用户手动 `start_mio.ps1` 启动，**不要**从 AI 会话代劳重启（会打断用户）。
- 若你看到 404，**先怀疑"进程没重启"，而不是"端点没生效"** —— 这是最容易误判的一条。

### 日常测插件用哪条命令（**都不需要那个活进程**）

| 目的 | 命令 | 耗时 |
|---|---|---|
| 日常快速反馈 | `cd packages/mao-pet; npm run test:fast` | ~1s |
| 验摄入链路（真实后端） | `cd packages/mao-pet; npm run test:e2e` | ~80s |
| 全量 | `cd packages/mao-pet; npm test` | ~80s |

**为什么 `test:e2e` 不需要活进程**：它把插件真实 `createHttpTransport` 的 `fetchImpl`
换成直接打 FastAPI `TestClient`（`import app.main`），**在进程内**跑真实 app。
因此它验的是"真实后端行为"，同时**绕开了旧进程这个环境坑** ——
**摄入链路的验证不依赖端口 8000**。

### 真机四条验收（7.6 ①~④）需要三件事同时就位

1. 主体侧 `window.__mioPetStrip`（**Lead 已实现**，见 §5）；
2. 用户重启后端（见上）；
3. 桌宠 Electron 窗口由用户手动 `start_mio.ps1` 启动。

⇒ 归 **task-3**（需用户在场）。

  - 拖动位置键 `mio-pet-strip-pos`、关闭态键 `mio-pet-strip-dismissed`（均 localStorage ⇒ 主体拥有、跨会话持久）

### 签名一致性

`packages/mao-pet/lib/strip.js` 与主体 `window.__mioPetStrip` 的 8 个方法签名**逐一对齐**，
以 `strip.js` 为权威。若需变更，**先改 `strip.js` 的 docstring 再改主体**，避免两端漂移。

## 6. 给主体实现者的最小骨架

```js
// 在桌宠主窗口初始化后注册（与 __mioPetBubble 同一位置）
window.__mioPetStrip = (function () {
  let dismissed = false, enabled = true, visible = false, styleId = 'default'
  const el = /* 你的可拖动胶囊元素 */ null
  const safe = (fn, fb) => { try { return fn() } catch (e) { return fb } }
  return {
    show: (text, o) => safe(() => {
      if (!enabled || dismissed || !el) return false
      /* 渲染 text；o.sticky 决定是否重置自动隐藏计时 */
      visible = true
      return true
    }, false),
    append: (t, o) => safe(() => { if (!enabled || dismissed || !el) return false; /* 追加 */ return true }, false),
    hide: () => safe(() => { /* 只隐藏内容，**不**碰 dismissed */ }),
    isVisible: () => safe(() => visible, false),
    isDismissed: () => safe(() => dismissed, false),
    setEnabled: (on) => safe(() => { enabled = on !== false }),
    applyStyle: (id) => safe(() => { styleId = String(id || 'default'); /* 落类 + 写 settings */ return styleId }, 'default'),
    info: () => safe(() => ({ visible, dismissed, enabled, styleId }), { visible: false, dismissed: false, enabled: false, styleId: '' }),
  }
})()

// ✕ 按钮：置 dismissed = true（并持久化），调用 hide()
// settings_changed 里：if (key === 'pet_strip_style') __mioPetStrip.applyStyle(value)
```
