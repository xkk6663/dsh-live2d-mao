# 插件市场 · 接口契约（冻结版 v1）

> 本文是 **Mio 插件市场**的唯一契约出处：后端清单格式、HTTP 接口、前端加载协议、事件名。
> 后端 / 前端 / 桌宠渲染端三方**各自照本文实现，互不读对方源码**。
> 改动本文件 = 破坏契约，必须三方同时改并重跑门禁。

---

## 0. 为什么需要它（一句话）

在此之前，插件是**写死在 `dist/index.html` 里的 `<script>` 标签**：装了才有、卸了还在、改了要重启。
本文引入中间的「清单层」，让 `dist/plugins/` 下的插件目录成为**可枚举、可热插拔的数据**，
而不是编译期的代码。

```
             ┌─────────────────────┐
             │ 插件清单 (catalog)   │  ← 可写、可枚举、可增删
             │ data/插件市场.json   │
             └──────────┬──────────┘
        GET /api/plugin/market/catalog
                        │
     ┌──────────────────┴───────────────────┐
     │                                      │
kernel/plugin-loader.js            live2d-pet/plugin-bus.js
（管理窗：动态插 script）            （桌宠窗口：动态插 script）
     │                                      │
manifest.js → __mioPluginRegistry    manifest → __mioPluginBus
     │                                      │
kernel/plugin-nav.js（导航/tab 显隐）   右键菜单聚合
```

**核心原则**：kernel **不认识任何具体插件**。它只读清单，按清单里的 `entry` 路径去加载。
桌宠本体（`pet`）是 `builtin`，恒可见、不可停用、不可下架，但**走同一套流程**。

## 1. 清单条目（catalog entry）—— 唯一的插件声明格式

落盘位置：`私人AI日记系统/数据/插件市场.json`

```json
{
  "version": 1,
  "updated": "2026-10-25T22:30:00+08:00",
  "plugins": [
    {
      "agentId": "dsh",
      "name": "DSH",
      "version": "1.1.0",
      "author": "Mio",
      "entry": "plugins/dsh/manifest.js",
      "panel": "plugins/dsh/dsh-panel.js",
      "accent": "#4F6BED",
      "description": "DSH 实时工作状态页 + 12 态图例 + 体检条目",
      "category": "agent",
      "builtin": false,
      "enabled": true,
      "added": "2026-10-25T22:30:00+08:00"
    }
  ]
}
```

### 字段表（★ = 必填）

| 字段 | 类型 | 说明 |
|---|---|---|
| ★ `agentId` | string | 插件唯一 id，`^[a-z0-9_-]{1,32}$`。**必须等于后端 `/api/companion/agents` 的 agent_id**（如果该插件占用总线身份）。重复 = 409 |
| ★ `name` | string | 显示名，≤40 字 |
| `version` | string | 语义化版本，缺省 `1.0.0` |
| `author` | string | 作者，缺省 `Mio` |
| ★ `entry` | string | **manifest 脚本路径，相对 `澪Agent应用/dist/`**。必须真实存在且落在 `dist/plugins/` 内 |
| `panel` | string | 面板脚本路径，同样相对 `dist/`。缺省不加载（`settingsTab` 声明了就必须给） |
| `accent` | string | 身份色 `#RRGGBB`，用于市场卡片与气泡 |
| `description` | string | 一句话说明，≤200 字 |
| `category` | string | `agent` / `ui` / `pet` / `tool` / `other`，缺省 `other` |
| `builtin` | bool | `true` = 宿主本体：**不可停用、不可下架**。缺省 `false` |
| `enabled` | bool | 期望启用态。缺省 `true`。真值以总线为准（见 §3.3） |
| `added` | string | 上架时间（ISO8601），后端自动填 |

### 路径安全（硬约束，后端强制）

- `entry` / `panel` 必须是**相对路径**，且 resolve 后仍在 `dist/plugins/` 之内（`realpath` 校验，防 `../` 与软链接逃逸）；
- **不接受** `http://`、`//`、绝对路径、`..`；
- 不存在的文件 → 400，错误信息里带具体路径，前端直接回显。

## 2. HTTP 接口（前缀 `/api/plugin/market`）

> 安全：不自己造鉴权。写端点依赖全站 `LocalControlMiddleware`（只接受本机回环 + 同源 + 拒绝 cross-site）。
> 前缀独立于 `/api/plugin/dsh`，**不影响 `dsh_adapter_selftest` 的路由白名单断言**。

| 方法 | 路径 | 作用 | 成功返回 |
|---|---|---|---|
| GET | `/catalog` | 全量清单 + 每个条目的实时状态 | `{ok, version, plugins:[Entry+State]}` |
| GET | `/plugins/{agentId}` | 单条 | `{ok, plugin}` |
| POST | `/plugins` | **上架**（登记一个已在 `dist/plugins/` 里的插件） | `{ok, plugin}` / 409 重名 / 400 校验失败 |
| PATCH | `/plugins/{agentId}` | 改元数据（name/version/author/accent/description/category/enabled）——**不可改 agentId/entry/builtin** | `{ok, plugin}` |
| DELETE | `/plugins/{agentId}` | **下架**（仅移除清单条目，**不动磁盘文件**）；`builtin` → 403 | `{ok, removed, files_kept:true}` |
| POST | `/plugins/{agentId}/enable` | 热插拔：`{enabled: bool}`。内置 → 403；不存在的插件自动注册进总线 | `{ok, agentId, enabled, bus}` |
| POST | `/reload` | 通告前端重扫（同时返回当前清单） | `{ok, plugins}` |
| GET | `/diagnostics` | 清单健康度：缺失文件 / 路径越界 / 重名 / 总线未注册 | `{ok, checks:[...]}` |

### 2.1 条目 + 实时状态（`Entry+State`）

```json
{
  "agentId": "dsh",
  "name": "DSH",
  "entry": "plugins/dsh/manifest.js",
  "builtin": false,
  "enabled": true,
  "bus": {
    "registered": true,
    "enabled": true,
    "status": "online",
    "phase": "idle"
  },
  "health": { "ok": true, "problems": [] }
}
```

- `bus` = 总线实时快照（`agent_bus_service.get(agentId)`）；**没占用总线身份的纯 UI 插件允许 `bus: null`**；
- `health.problems` 可能值：`missing_entry` / `missing_panel` / `path_escape` / `duplicate_id` / `not_registered`。

## 3. 前端加载协议

### 3.1 `kernel/plugin-loader.js`（管理窗）—— 唯一加载器

```
__mioPluginLoader.load()      ① GET /catalog
                              ② for each health.ok && (builtin || enabled):
                                  注入 <script data-mio-plugin="{agentId}" src="/agent-app/{entry}?v={version}">
                              ③ manifest 自注册进 __mioPluginRegistry
                              ④ 再加载面板脚本（若 disabled 则跳过，面板不下载）
__mioPluginLoader.unload(id)  移除该插件的 manifest + 面板脚本 + DOM 残留，通知 nav 重算
__mioPluginLoader.reload()    unload 全量 → load 全量（热插拔落点）
```

**加载顺序（硬约束，不得打乱）**：

```
kernel/plugin-registry.js → kernel/plugin-loader.js → plugins/pet/manifest.js(builtin)
  → …loader 异步加载清单内插件… → kernel/plugin-nav.js
```

`?v=` 版本参数取条目里的 `version`，**改完插件就不用改 index.html 了**（这正是动态加载换来的）。

### 3.2 重复加载 / 幂等

- 脚本标签带 `data-mio-plugin="{agentId}"`；已存在则不重复插；
- 插件自身仍必须遵守 `if (window.__xxxLoaded) return`（原有 R6 规则不变）。

### 3.3 启用态的唯一真值

| 插件类型 | 判定 |
|---|---|
| `builtin: true` | 恒可见。不看 `enabled`，不提供启停入口 |
| 普通插件 + 占用总线身份 | 以 `/api/companion/agents` 的 `enabled` 为准（现有规则不变） |
| 普通插件 + 不占总线（`bus:null`） | 以清单的 `enabled` 为准 |

统一入口仍是 `__mioPluginRegistry.visible(id)`，**不许别处再写一套**。

### 3.4 事件

| 事件 | 派发者 | 载荷 | 监听者 |
|---|---|---|---|
| `mio:plugins-changed` | `__mioPluginLoader`（变更后 `window.dispatchEvent`） | `{reason, plugins}` | 市场面板、nav |
| `__mioPluginRegistry.onChanged(cb)` | registry | `{type:'manifest-registered'\|'manifest-removed', id}` | nav |
| WS `agents_snapshot` | 后端总线（已有） | 快照 | 桌宠渲染端（已有） |

## 4. 桌宠渲染端（`live2d-pet/plugin-bus.js`）

- 复用**同一份** catalog（`GET /api/plugin/market/catalog`），不另建清单；
- 新增 `unregister(id)`：卸载时先从 `plugins`/`menuEntries` 删除，再 `unmount(id)`，避免菜单残留（现有 bug：`unmount` 后 `menuEntries` 还在，只是被 `mounted` 过滤）；
- 桌宠窗口**没有** `window.__mioPluginRegistry`，它的插件都是 `register({id, agentId, menuItems, onMount, onUnmount})` 的内联模块；
  因此渲染端只用 catalog 决定「哪些 agentId 的插件应该挂载」，不参与 `<script>` 注入（避免两套加载器）。

---

## 5. 市场 UI（`plugins/market/`）

- 自身也是一张卡片：`agentId: 'market'`，`builtin: false`（可被下架——下架后就看不见市场了，这是可接受的极端操作，删除前 UI 会警告）；
- 设置页 tab：`settingsTab: { id: 'market', label: '插件市场', order: 900, panel: 'market-panel' }`；
- 只调 `/api/plugin/market/*` 与 `/api/companion/agents/*`，**不读其它插件的接口**（R2）；
- 启停按钮 = `POST /plugins/{id}/enable` → 成功后 `__mioPluginLoader.reload()` + `__mioPluginNav.refresh()`；
- 上架表单 = `POST /plugins`，字段校验在前端先跑一遍，后端错误原样回显。

## 7. 真机踩过的坑（每一条都是实测出来的，别重蹈）

### 7.1 `health.ok` 不能把 `not_registered` 算成致命

总线注册是**适配器的导入副作用**（`dsh_adapter` 在 import 时 register），只在 `main()` 里发生。
于是任何没跑 `main()` 的入口（自检、TestClient、另一个进程里的探针）看到的都是**空总线**，
每个插件都被判 `not_registered` → 若它计入 `health.ok`，loader 会把**所有插件整个跳过**，
表现为「左侧导航和设置页 tab 集体消失」。
**结论**：`health.ok` 只由结构性缺陷决定（`missing_entry` / `missing_panel` / `path_escape` / `duplicate_id`）；
`not_registered` 仍写进 `problems` 供人看，但不拦加载。

### 7.2 卸载前必须先让插件的"自愈"停手

许多面板做了 R4 自愈（发现按钮没了就补回来）。loader 卸载时也会摘按钮，
面板的自愈会当成"Vue 又删了"，**立刻补一个回来** → 用户看到「插件停了，入口还在」，
而且会和 loader 打乒乓。
**结论**：loader 卸载流程必须是 ① 先取 nav 快照 → ② **调插件 `dispose()`** → ③ 删 registry → ④ 摘 DOM。
插件侧 `dispose()` 负责停轮询 + `MutationObserver.disconnect()` + 摘自己的 DOM；
没实现 `dispose()` 的插件，其自愈也应自查 `registry.get(id)` 是否为 null。

### 7.3 `reload()` 必须"先取清单，再动手"

旧实现先无条件卸载全部插件、再去拉清单。中间只要请求失败（后端重启 / 网络抖动），
界面**已经被清空了**，`catch` 里那句"保持现有界面不变"就是空话。
**结论**：先 `fetchCatalog()`，成功后才 unload + load；失败直接 return，一个插件都不动。

### 7.4 侧栏避让：页面里有**两个** `<nav>`，而且宽度会变

- `nav.main-nav`（侧栏，展开 193px / 折叠 41px）—— 真正遮挡内容的那一个；
- `nav.companion-tab-bar`（整行 tab 条，宽 ~1198px）—— 不该参与避让。

`querySelector('nav')` 可能命中任意一个（实测见过 41px 和 1198px，后者算出 1210px 内边距）。
侧栏在市场页刚打开的那一拍常常还是**折叠态**，此刻测量会把避让值算小。
**结论**：按 `.main-nav` 精确取；用 **CSS 声明宽度**（稳定设计值）而非此刻测量；
兜底展开态 193px；避让量 = `侧栏右边缘 − 内容容器左边缘 + 12`（不是"侧栏宽度"）。

### 7.5 插件版本号固定 `1.0.0` 时，改了代码浏览器拿不到新版

loader 用 `?v={version}` 做缓存键，而清单里所有插件的 `version` 都是 `1.0.0`。
改完插件代码后，用户浏览器仍会用旧缓存 —— 表现为"我明明改了却没生效"。
开发期用硬刷新（Ctrl+Shift+R），或改清单里该插件的 `version` 以破坏缓存。
**这条坑我踩了两次**（改 loader 与改面板各一次），改任何插件代码后务必升版。

### 7.6 `reload()` 必须是**差异重载**，不能"全卸全装"

用户实测：「按了启用/停用，插件市场自己的左侧入口也没了」。
根因是两个因素叠加：

1. 旧 `reload()` 先把**所有**插件卸载再全部重装 —— 点 DSH 的开关，市场自己也被卸载；
2. 插件脚本都有幂等守卫（`if (window.__mioXxxLoaded) return`），
   重插 `<script>` **不会重新执行** → 被 dispose 摘掉的导航按钮永远回不来。

**结论**：`reload()` 只动真正变化的插件：

| 情形 | 动作 |
|---|---|
| 新清单仍 enabled 且已在场（`entries[id]` + `manifestOf(id)` + `findScript(id)` 都在） | **原样保留**，不 dispose、不重插 |
| 清单里消失 / 变停用 | 卸载 |
| 新出现 / 停用→启用 | 加载 |

### 7.7 `settingsTab.panel` 是**导出名**，`entry.panel` 是**脚本路径**

两者同名不同义，混用会静默失效：

- `manifest.settingsTab.panel`：`'dsh-panel'`（挂在 `window['dsh-panel']` 上的**导出名**）；
- 清单条目 `panel`：`'plugins/dsh/dsh-panel.js'`（**脚本路径**）。

`disposePlugin` 曾经用后者去拼 `__mioPlugins/dsh/dsh-panel.jsPanel` 这种不存在的名字，
于是 `dispose()` 静默没被调用 → 停用后入口还在。
**而且 DSH 根本没有 `settingsTab`**（它只做左侧功能页），所以必须按 `agentId` 推导：
`<id>-panel` 与 `__mio<Camel>Panel` 两种形态都要试。

### 7.8 下架必须清理**自建**的总线身份

`set_enabled()` 会为纯 UI 插件自动注册总线身份（`adapter='plugin_market'`）。
下架若只把 `enabled` 拨成 False、不 `unregister`，
`/api/companion/agents` 就永远多一条 offline 幽灵身份，
**右侧 Agent 边栏一直显示一个已经下架的插件**（用户原话："探针没清"）。

**结论**：下架时按**身份归属**决定 ——
`adapter == PLUGIN_MARKET_ADAPTER` 的身份（市场自己建的）→ `unregister` 摘掉；
其它 adapter（`dsh_adapter` / `cloud_feiyu` …，真实链路）→ 只拨停用，**绝不删**。

### 7.9 `nav.mode: 'host'` 的按钮必须由 loader **自己隐藏**

用户实测：「停用大肥鱼插件后左侧大肥鱼界面没消失」。

`feiyu` 的 `nav.mode` 是 `'host'` —— 按钮由**原版 Vue 渲染**，插件没有自建，
所以 loader 按铁律 R9「绝不删 host 按钮」是对的。问题在于**隐藏这件事原先没人做**：

```
applyVisibility() 按 navRules 遍历 → 决定每个插件的按钮显隐
navRules 从 __mioPluginManifests 聚合
卸载时把 manifest 删了 → navRules 里没有 cloud_feiyu 这一项
→ 循环根本走不到它 → "该隐藏"的规则自己先没了 → 按钮原地不动
```

**结论**：两种模式在卸载时走**不同**动作，且都由 loader 负责：

| nav.mode | 卸载时 | 启用时 |
|---|---|---|
| `own`（插件自建按钮） | **删除**节点 | 插件 `revive()` / `ensureNav()` 重建 |
| `host`（Vue 渲染按钮） | **`display:none` + `data-mio-plugin-hidden="<id>"`** | loader 在 `loadPanel` 入口无条件复位 display |

注意 host 的复位点必须放在 `loadPanel` **入口**而不是 `.then()`：
面板"已存在 → 提前 return"那条路径不进 then，隐藏的按钮就会一直藏着。
