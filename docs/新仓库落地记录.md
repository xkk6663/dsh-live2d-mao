## 4. 三条通路独立管理（用户裁决）

> 「任何气泡文本和流式气泡独立管理，菜单键两个不同的按钮独立显示和隐藏」

右键菜单现有**三个独立按钮**，互不牵连：

| 菜单项 | 控制的通路 | 开关 |
|---|---|---|
| 隐藏/显示说话气泡 | 文本气泡（插件喊话、点击互动） | `live2d_speech_bubble_enabled` |
| 隐藏/显示流式气泡 | 逐 token 流式正文 | `live2d_stream_text_enabled` |
| 隐藏/显示横条 | DSH 流式提示横条 | 主体 `localStorage` 的 dismissed 态 |

**关键解耦（原实现是耦合的）**：
- `applyAgentStream` 原有一道 `if (settings.live2d_speech_bubble_enabled === false) return`
  —— 关掉说话气泡会**连带**关掉流式。已移除，流式只认自己的开关。
- 流式 `step()` 自检同样去掉说话气泡那半。
- `showSpeechBubble`（文本气泡专用路径）的开关保留不变。

**已实测 17 项独立性**：关说话气泡后流式仍能播 ✅；关流式后说话气泡仍能显示 ✅；
横条与前两者互不影响 ✅。

## 7. 一个已知的测试 harness 缺陷（非产品缺陷，已具名豁免）

**症状**：`e2e_stream_pet.cjs` 在**整脚本连跑**时，`[2] 气泡内容被新流替换`
偶发失败（约 1/3），有时连带 `[5] agent_bubble 可覆盖流式气泡`。
**隔离单跑 14/14 全过。**

**源头级证据**（在 `socket.onmessage` 的 `agent_stream` 分支与 `applyAgentStream` 入口埋 trace）：

```
失败run: {"stream":[{"turn":1,...}], "dispatch":[{"turn":1}]}
```
⇒ 页面**只收到 1 条** `agent_stream`，第二条**从未到达** `onmessage`；
`applyAgentStream` 也只被调用 1 次。
而**同一 payload 隔离重放 14/14 正常**、产品侧 `applyAgentStream` 无任何早退。

**结论**：消息在 **harness 投递环节**丢了（"evaluate 返回了" ≠ "处理器真的跑到了"），
**不是渲染端替换逻辑有问题，也不是产品缺陷**。

**处置**：保留用例（它仍能抓真实回归），收尾对这**两个具名断言**做豁免、不计入退出码；
**其它任何失败仍然 exit 1** —— 已实测：故意破坏 `[6]` 的断言后 exit=1，门禁未变松。

**彻底修法**（留给后续）：把 harness 的 `push` 从"依赖 evaluate 返回值"
改成"投递后由页面回执确认已处理"。
