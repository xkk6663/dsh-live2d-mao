# 版本维护与迭代指南

> 回答：上架市场后能不能更新版本？自检界面的「检查更新」按钮怎么回事？日常怎么发版？

---

## 0. 一句话结论

**能更新，而且很简单**：上架市场后，你只需在 npm 上发一个新版本，市场会自动检测并提示用户更新。catalog 条目里的版本号/下载量由市场**每日自动刷新**，不用你手动改。

---

## 1. 三个「版本」各是什么，别混

| 概念 | 在哪 | 谁改 | 用途 |
|---|---|---|---|
| **npm 包版本** | `packages/dsh-live2d-mao/package.json` 的 `version` | 你（`npm version` + `npm publish`） | **唯一真版本源**：`dsh plugin add`、市场更新、自检更新检查都盯它 |
| **仓库版本** | `CHANGELOG.md` 顶部 | 你（手写） | 自检界面「关于」页显示的版本号（`read_mio_version()` 读这里） |
| **catalog 条目版本** | awesome-dsh-plugin 的 plugins.json | **市场自动** | 只在首次上架时你提一次 PR，之后每日探测自动更新 |

> ⚠ 前两个要**手动保持一致**：发版时既要 `npm version`，也要在 CHANGELOG 顶部加对应条目，否则自检界面显示的版本会落后于 npm。

## 2. 日常发版流程（标准三步）

假设现在 1.0.0，要发 1.1.0：

```powershell
cd C:\Users\xiao1\Mao-dsh-pet

# ① 改代码，跑门禁（AGENTS.md §6 四条）
#    - 插件:  cd packages/dsh-live2d-mao && node --test test/*.test.js
#    - 后端:  cd 私人AI日记系统/backend && .venv\Scripts\python.exe -m app.agents.dsh.dsh_adapter_selftest
#    - 前端:  cd 澪Agent应用 && npm run guard && node tests/e2e_stream_pet.cjs

# ② 升版本号（npm 会自动改 package.json + 打 git tag）
cd packages/dsh-live2d-mao
npm version patch   # 1.0.0 → 1.1.0（或 minor / major）

# ③ CHANGELOG 顶部加一条（自检界面版本源）
#    手动编辑 CHANGELOG.md，把新版本条目写到最上面

# ④ 提交 + 推送 GitHub
cd C:\Users\xiao1\Mao-dsh-pet
git add -A && git commit -m "v1.1.0: <改动说明>"
git push origin dsh-only-slim:main

# ⑤ 发布 npm（会提示更新检查的版本号）
cd packages/dsh-live2d-mao
npm publish
```

> `npm version patch` 会自动：改 `package.json` 的 version + 打 `v1.1.0` tag + git commit。你只需补 CHANGELOG 和 push。

### 版本号规则（semver）

| 命令 | 效果 | 何时用 |
|---|---|---|
| `npm version patch` | 1.0.0 → 1.0.1 | 修 bug |
| `npm version minor` | 1.0.1 → 1.1.0 | 加功能（向后兼容） |
| `npm version major` | 1.1.0 → 2.0.0 | 破坏性改动 |

## 3. 上架后市场的更新机制（源码级确证）

dshmarket 的更新检测（`updates.js` 第 4 行注释）：

> **「npm install 对比 npm latest dist-tag」**

即：用户装了 1.0.0，你发 1.1.0 到 npm 后：

1. 市场每日刷新 catalog（版本号/下载量自动更新）
2. 用户打开市场 → 插件卡片显示「可更新 1.1.0」
3. 点「更新」→ 市场自动 `pnpm add dsh-live2d-mao@latest`

**你全程不用碰 catalog 条目**——只有首次上架提一次 PR，之后全靠 npm 版本号驱动。

## 4. 自检界面的「检查更新」按钮（已修复）

- **之前**：查 PyPI 的 `mio-companion`（Mao 时代旧包名，从未发布）→ 永远显示「未接入」，等于失效
- **现在**：查 **npm 的 `dsh-live2d-mao`**（`about_service.check_update` 已改），与市场、`dsh plugin add` 三者版本源统一

实测：`check_update('1.0.0')` 正确返回 `latest: 1.0.0`、`has_update: false`。

> 这个按钮是**后端**功能（自检界面在桌宠后端里），改完要重启后端才生效。

- [ ] 改代码 → 跑四条门禁全绿
- [ ] `npm version patch/minor/major`
- [ ] CHANGELOG 顶部加版本条目

- [ ] `npm publish`（npm，会触发市场自动更新）

## 6. 常见问题

**Q：忘了改 CHANGELOG 会怎样？**
自检界面「关于」页显示旧版本号（它读 CHANGELOG 顶部）。npm 和市场不受影响（它们读 package.json）。

**Q：npm publish 又要 2FA？**
是。你那个 bypass 2FA 的 token 还在 `.npmrc` 里，直接 `npm publish` 即可。若 token 过期，重新生成一个。

**Q：上架 PR 一直没 merge 怎么办？**
不影响功能——`dsh plugin add dsh-live2d-mao` 始终能装。PR 只是让市场里「能搜到」，merge 前用户得知道包名。

**Q：桌宠后端和 npm 插件是两个东西，版本怎么统一？**
桌宠后端（`私人AI日记系统/`）**不发布**，只在本地 git 仓库迭代；npm 插件（`packages/dsh-live2d-mao/`）才是对外发布的。CHANGELOG 顶部版本号反映的是「整个项目」的版本，两者一起推进即可，不必强分。
