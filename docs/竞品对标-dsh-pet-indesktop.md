## 0. 一句话结论

dsh-pet-indesktop 走的是**「独立桌面 App」**路线（PySide6 透明置顶窗口，脱离 DSH 运行时），
而不是我们这种**「DSH 插件 + 独立 Electron 壳」**路线。它的护城河是**桌宠本体体验**（动画、
拖拽物理、多开、彩蛋），弱点是**与 DSH 工作状态的联动较浅**（只有 5 态 + 富事件气泡，
审批/提问是"引导回 DSH 界面处理"的纯提示，不做回传闭环）。

**我们真正的代差优势没变**：12 态语义总线 + Live2D 骨骼动画 + 逐 token 流式 + 审批/提问
**回传闭环**（它没有的）。它值得借鉴的是**桌宠本体的交互打磨**和**工程纪律**（文档体系）。

## 1. 它有什么（按我们的关注点分类）

### 1.1 桌宠本体体验（它极强，我们可借鉴）

| 能力 | 它 | 我们 | 借鉴价值 |
|---|---|---|---|
| **拖拽物理**（惯性、抛掷、弹簧阻尼、静止下坠） | ✅ 极精细 | 基础拖动 | ★ 高——手感是桌宠的核心体验 |
| **边缘探头**（拖到屏幕边自动探头姿态） | ✅ | ❌ | 中 |
| **撞飞彩蛋 / 黄金回旋**（连点加速） | ✅ | ❌ | 低（彩蛋，非刚需） |
| **锁定位置 / SHIFT+拖动** | ✅ | ❌ | 中（防误拖） |
| **不透明度 10%~100% 可调** | ✅ | ❌ | 中 |
| **多开**（单进程孵化多只，独立配置/会话） | ✅ 单进程多宠 + 共享解码 | 单只 | 低（我们定位是"DSH 的脸"，单只即可） |
| **系统托盘**（隐藏/显示、开机自启、菜单） | ✅ | 部分 | 中 |
| **待办提醒** | ✅ | ❌ | 低 |
| **每日一签 / 天气 / 歌词 / 报时** | ✅ 一堆 | ❌ | 低（偏离 DSH 专用定位） |

### 1.2 DSH 联动（它弱，我们强）

| 能力 | 它 | 我们 |
|---|---|---|
| 状态态数 | 5 态（thinking/working/attention/error/idle） | **12 态** |
| 审批/提问 | **纯提示常驻气泡**（引导回 DSH 界面处理，不做回传） | **回传闭环**（横条弹按钮→回传 outcome） |
| 逐 token 流式 | ❌ | ✅ |
| Live2D 骨骼动画 | ❌（WebM 视频素材） | ✅（PixiJS + Cubism） |
| 多会话聚合 | attention>error>working>thinking>idle 简单聚合 | 气泡栈优先级 + 活跃聚焦 |

### 1.3 工程纪律（它极强，**最该借鉴**）

这是 dsh-pet-indesktop 给我印象最深的地方——它的文档和流程体系非常成熟：

- **`AGENTS.md`**：工程纪律权威出处（架构红线、变更纪律、"Context pointers"改哪块先读哪份文档）
- **`docs/INDEX.md`**：全文档索引，新文档必须登记互链
- **架构红线机器守卫**：`tests/test_architecture.py` 用常量值 + 校准日期守「window.py 只许瘦不许胖」等约定
- **设置项三处登记**：默认值 dict + reload 白名单 + 配置 schema 快照测试
- **每条 PR 交三份证据**：修改文件说明 + 实测性能分析 + 实机运行记录
- **时序测试纪律**：禁止固定 sleep、禁止赌目录枚举顺序、用 monotonic 时钟

## 2. 值得借鉴的点（按性价比排序）

### 🏆 最高优先：工程纪律体系（零代码成本，纯流程收益）

我们现在的文档是「一堆 Markdown 各写各的」，缺一个**权威入口 + 红线守卫**。借鉴它的：

1. **`AGENTS.md` / `docs/INDEX.md`**：一张索引说清「改哪块先读哪份文档」，新文档必须登记
2. **架构红线机器守卫**：把「live2d-pet.js 只许在核心 API 边界改」「插件不碰核心 DOM」这类铁律写进测试断言（我们现在靠注释和人工守，会退化）
3. **提交前三道门**的明确化：我们现在有 guard + 自检 + E2E，但没固化成一个"提交前必跑"的单一命令

### 🥈 中优先：桌宠本体交互打磨

- **拖拽物理**（惯性/弹簧/抛掷）——手感是桌宠的灵魂，我们目前只有基础拖动
- **锁定位置 + SHIFT 拖动**——防误拖，成本低
- **不透明度可调**——简单但实用

### 🥉 低优先（偏离 DSH 专用定位，不建议跟）

- 天气/歌词/报时/每日一签/待办/彩蛋——这些让桌宠变「陪伴型」，但我们定位是「DSH 工作状态的脸」，别跑偏
- 多开/多宠——DSH 单 Agent 场景用不上

## 3. 我们的护城河（它做不到的，别丢）

| 能力 | 说明 |
|---|---|
| **12 态语义总线** | 它只有 5 态，我们 thinking/planning/executing_tool/streaming/waiting_input/voice/awaiting_approval/… 全语义 |
| **Live2D 骨骼动画** | 它用 WebM 视频（素材固定、不能实时表情/口型），我们是 PixiJS+Cubism 实时骨骼 |
| **逐 token 流式 + 横条** | 它没有流式 |
| **审批/提问回传闭环** | 它只"引导回 DSH 处理"，我们横条直接弹按钮回传 outcome |
| **232+ 项测试 + E2E** | 它有一堆测试但我们的语义正确性覆盖更聚焦 |

## 4. 后续开发方向建议（综合两轮竞品 + 当前状态）

1. **工程纪律体系**（最高优先，零成本）：建 `AGENTS.md` + 架构红线机器守卫，把"插件不碰核心 DOM""横条只经 `__mioPetStrip`"等铁律从注释变成测试断言
2. **桌宠本体交互打磨**：拖拽物理（惯性/弹簧）、锁定位置、SHIFT 拖动、不透明度
3. **余额记账**（之前 whale 对标遗留）：如果目标是"DSH 用户完整桌宠"，余额是刚需（dsh-pet-indesktop 也有，且明说参考了 whale）
4. **审批/提问回传的真机联调**：需先切 DSH 审批策略 `never→ask`，验证横条按钮回传
5. **发布**（Phase 4）：npm + README + PROVENANCE + icon.png，让 mao-pet 真正可 `dsh plugin add`
